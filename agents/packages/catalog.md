# Package Catalog

One paragraph per package, grouped by domain — what each package owns and where its boundary sits. This is the tier between the name-only grouping in [`AGENTS.md`](../../AGENTS.md#package-map) and the long-form per-package detail in [map.md](map.md).

Run `npm run api package=<name>` to list one package's exported function signatures. A bare
`npm run api <name>` is a SEARCH, not a selector: it matches package names and function names across
every package, so `npm run api color` returns 25 packages — each result sits under its owning package
heading, which is the only thing that says who exports it.

State machines: `@flighthq/statechart` is the concurrent data-only guarded graph shared by gameplay and Rive composition: immutable charts, mutable per-actor typed-array instances, typed inputs/triggers, open state-kind keys, exit/blend reporting, sentinels/explanations, and opt-in instance signals. It performs no animation and is distinct from `flow`'s closure-bearing covering screen stack.

Scene resource acquisition keeps URL acquisition, synchronous format parsing, scene construction, content-resource resolution, and renderer/GPU realization explicit. `@flighthq/scene3d-resources` `loadScene3DDocumentFrom*Url` functions stop at renderer-neutral `Scene3DDocument`; `@flighthq/scene2d-resources` provides the same staged boundary for `Scene2DDocument` plus named asset/application slots. The standalone `@flighthq/swf` domain supplies the first structural named-graph importer through that open registry: recursively nested uncompressed first-frame graphs across legacy and current placement/removal records plus fresh/move/replacement state, with names, transforms, linkage, and RECT/embedded-image/lossless-bitmap/video/sprite authored extents. A revision-pinned external Ruffle `FWS` verifies the named-slot boundary, including zero-bit empty-shape bounds, without adding a binary or network test dependency; later MovieClip frames and visual/compression coverage remain staged. In both resource designs, resolve reconciles a caller-ready working set synchronously, while load adds the operation-scoped Promise/progress boundary.

Core: `@flighthq/types` (header layer — all shared types), `@flighthq/entity` (entity/runtime primitives), `@flighthq/geometry` (rectangles, vectors, matrices, quaternion, bounding volumes (AABB, OBB, sphere, plane, frustum, capsule), Ray3D intersection, closest-point, pools), `@flighthq/math` (scalar utilities — interpolation, angles, random, hashing, statistics; pure free functions), `@flighthq/layout` (headless anchor/flex/grid rectangle resolution over flat parent-before-child trees into caller-owned numeric buffers; open opt-in resolver registry, types-only dependency, with constraints/text/table semantics/scene binding outside), `@flighthq/node` (graph hierarchy, transforms, bounds, appearance), `@flighthq/signals` (typed signals and slots with priority and cancellation).

Rendering: `@flighthq/render` (registration, render state/queue, update pipeline, transform/color propagation), `@flighthq/render-gl` (WebGL2 backend core — subject-agnostic GPU plumbing: state/context, targets + pool, textures/samplers, shader + material registries, cached pipeline state, fullscreen/quad passes, readback, context-loss; 3D (data primitives; the `Mesh`/scene node is `@flighthq/scene3d`, materials are `@flighthq/materials`, and the forward renderers are `scene-gl`/`scene-wgpu`): `@flighthq/mesh` (3D mesh geometry — interleaved vertex/index buffers, attribute layouts, parametric primitive builders, normal/tangent/bounds computation producing `MeshGeometry`), `@flighthq/lighting` (3D light data layer — ambient/hemisphere/directional/point/spot/area descriptors, IBL `Environment`, photometric `LightUnit` conversions, descriptor-side culling/luminance), `@flighthq/texture` (GPU texture-binding descriptors — sampling state (wrap/filter/anisotropy), color space, UV transform, cubemap aggregate, and the dynamic `VideoTexture` (a VideoResource-backed per-frame source with a `frameId` upload dirty-gate, sampled through the same uv-transform path a Texture uses)), `@flighthq/camera` (the unified camera math package — `Camera3D` perspective/orthographic projection descriptors, view/view-projection matrices, picking rays, world→screen projection, frustum extraction + culling, and (absorbed from the former `@flighthq/camera2d`) the 2D `Camera2D` world↔screen/follow/deadzone/zoom/parallax/visible-bounds math; a 2D bundle pays nothing for the 3D half), `@flighthq/animation` (target-free animation core — keyframe sampling, clip/channel bundling, playback control; scene/sprite binding layers interpret results), `@flighthq/skeleton3d` (skeletal animation — joint hierarchies, inverse-bind matrices, skin-palette computation for GPU upload), `@flighthq/picking` (camera-ray scene selection — composition over `@flighthq/scene3d` raycast + `@flighthq/camera` unprojection), `@flighthq/scene3d-formats` (3D scene/mesh file parsers — glTF 2.0/USD/OBJ into the scene/mesh/material/animation graph).

Resources: `@flighthq/image` (ImageResource entity lifecycle — create, clone, dispose, invalidate, DOM-based loading (URL/bytes/Base64/Blob), same-origin check; re-exports `detectImageMimeType` from image-codec), `@flighthq/image-codec` (DOM-free byte↔pixel seam — MIME-keyed decoder/encoder registry, `decodeImage`/`decodeImagePremultiplied`/`encodeImage` dispatchers, `detectImageMimeType` MIME sniffing, opt-in web `createImageBitmap`/`OffscreenCanvas` registrars), `@flighthq/font`, `@flighthq/video`, `@flighthq/audio`, `@flighthq/binpack` (general 2D rectangle bin-packer — the geometry primitive underneath texture-atlas/sprite-sheet/tileset/UI layout; Game: the 2D game camera (`Camera2D` — world↔screen `Matrix`, follow/deadzone/world-bounds clamp, zoom-at-point, parallax offsets, and the visible world AABB for culling feeding `@flighthq/spatial`) is **absorbed into `@flighthq/camera`** alongside `Camera3D`; the former `@flighthq/camera2d` package no longer exists as a standalone unit. `@flighthq/collision` (2D narrow-phase collision — discrete shape-vs-shape overlap between plain-data colliders (circle, AABB, oriented box, convex polygon, segment, point), returning a `CollisionManifold` (overlap boolean + minimum-translation `normal` + penetration `depth`) rather than just a boolean; a shared separating-axis (SAT) core drives the AABB/OBB/convex-polygon pairs with circle and point/segment special-cased, plus `getCollisionShapeContainsPoint` and `testSegment*Collision` queries. `out`-parameter and allocation-free in the hot path. Distinct from `@flighthq/geometry` (whose `Aabb`/`Obb`/sphere are 3D bounding volumes) and `@flighthq/interaction` (pointer hit-testing against display objects); this is general 2D collider-vs-collider detection decoupled from the scene graph, the layer a physics step or trigger system queries after a broadphase. Phase 1 (discrete overlap + manifolds) and the phase-3 contact-point manifolds are built: `collide*ContactManifold` + `collideContactManifold` resolve up to two world-space contact points with per-point depth and a frame-stable warm-start `featureId`, in a parallel lane so an overlap-only bundle never links the clipping machinery. Swept/time-of-impact and ray hit results are chartered later phases), `@flighthq/flow` (application mode/screen flow-state stack — a plain-data stack of application states (boot, menu, play, pause, game-over) with a paired enter/exit/pause/resume/update lifecycle driven by push/pop/replace/clear transitions and direct lifecycle callbacks (single-owner, deterministic order — not signals). `FlowState = {name?, onEnter?, onExit?, onPause?, onResume?, onUpdate?, updateBelow?, renderBelow?}` and `FlowStack = {states}` (top = last). `pushFlowState` pauses the old top then enters the new; `popFlowState` exits the top then resumes the revealed one; `replaceFlowState` swaps the top (exit+enter, no pause/resume of the one below); `clearFlowStack` exits top-to-bottom. `updateFlowStack` ticks the top and walks down through any `updateBelow` overlays; `getFlowStackVisibleStates` fills an `out` array with the top plus its contiguous `renderBelow` run, bottom-to-top. Plus `getActiveFlowState`/`getFlowStackDepth`. This is the _screen/mode_ stack (flow control), not save/serialization data; depends on `@flighthq/types` only, no display/renderer/scene graph), `@flighthq/snapshot` (immutable recoverable-state captures — `captureSnapshot(source)` deep-clones (`structuredClone`) then deep-`Object.freeze`s a plain state object into a frozen `Snapshot<T>` (= `DeepReadonly<T>`), `restoreSnapshot(snapshot, target)` deep-assigns it back into live mutable state in place (preserving identity, resizing arrays), `interpolateSnapshots(a, b, t, out, schema?)` clamps `t` and `lerp`s numeric leaves present in both while snapping non-numerics to `b` (an optional dotted-path `SnapshotSchema` restricts which numerics lerp), and `equalsSnapshot(a, b)` deep-compares. The save/undo/netcode/replay primitive over the app's plain model — sibling of `flow`'s flow-control stack; operates on plain data, does not own the state, no persistence format. Depends on `@flighthq/types` + `@flighthq/math` only), `@flighthq/spatial` (2D broadphase spatial index — the O(n) locality filter that feeds `@flighthq/collision`'s narrow-phase: insert/update/remove objects by id + AABB, then enumerate deduplicated candidate overlapping pairs (`querySpatialPairs`, each unordered pair once, never (a,a)) or query by region/point/ray. A swappable `SpatialIndexBackend` seam with `createUniformGridSpatialBackend(cellSize)` as the P1 default (quadtree/sort-and-sweep are chartered P2/P3 drop-ins behind the same operations); region/point/ray results are grid candidates confirmed against real bounds. Bounds + opaque id only — no shape, velocity, or scene node. Distinct from `@flighthq/geometry` (3D AABB math it builds on) and `@flighthq/collision` (the narrow-phase it feeds)).

Input/text: `@flighthq/input` (full input library — keyboard/pointer/wheel/gamepad/text normalization over 15 typed signals, held-state snapshots, per-frame edge queries, gamepad semantic naming with dead-zone math, key-repeat synthesis, pointer capture, coalesced pointer events), `@flighthq/textinput` (editable-text-field behavior — caret/selection model, text insertion/deletion/replacement, keyboard commands, input restrictions, password masking, undo/redo, word/line selection, focus managers (editable + read-only selectable)), `@flighthq/textlayout` (renderer-agnostic glyph layout — line breaking, alignment, justification, wrapping, rich text composition), `@flighthq/textshaper` (text-shaping seam — `measureText`, `shapeTextRun`/`shapeTextRuns` over a swappable `TextShaperBackend`; Application: `@flighthq/application` (main loop — start/stop/pause/resume/step, frame-rate control, fixed-timestep, FPS metrics over a swappable `LoopBackend`; plus windowing — `ApplicationWindow` state/control, multi-window registry, pointer-lock, fullscreen over a swappable `WindowBackend`), `@flighthq/intl` (locale-aware formatting over the ECMAScript `Intl` API — a pure utility, no backend: cached number/currency/percent/unit/compact, date/time, list, relative-time, plural/ordinal, and collation wrappers keyed by `(locale, options)`), `@flighthq/log` (leveled structured logging — `log(level, data, channel?)` with severity wrappers, multi-sink fan-out (console/memory/file/buffered/rate-limited/sampled/filtered/fanout), text/JSON formatters, timing/spans, groups, assertions, redaction), `@flighthq/debug` (opt-in debug control panel — the one import that switches on Flight's diagnostics: per-channel subsystem logging, guard checks, a dev console sink, timing/markers; not importing it costs production nothing), `@flighthq/useragent` (pure user-agent string parser — `navigator.userAgent` → browser/OS/engine/device data; a utility, no backend seam), `@flighthq/xml` (XML parsing — text into a traversable document model), `@flighthq/media` (runtime playback layer — Web Audio channels, an audio mixer with a bus graph (master gain, per-bus gain/pan/mute, routing), and HTMLVideoElement video channels), `@flighthq/sdk` (convenience barrel).

**Platform Integration Suite** — flat free functions over a swappable `*Backend`; web backends are installed explicitly via `enableHostWeb()` (or per-capability `enableHostWeb*()`) from `@flighthq/host-web`, and native hosts replace via `set*Backend`. Three ambient-language capabilities (net, socket, textsegment) stay inline with a lazy-install default. Precedence: custom (`set*Backend`) > host (`enableHostWeb*`) > sentinel. Command capabilities: `get*Backend`/`set*Backend`. Event capabilities: signal entity with `create*`/`attach*`/`detach*`/`dispose*`. Sentinels serve when no backend is installed, never throw.
