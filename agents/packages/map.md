# Package Map

Full per-package descriptions for the Flight SDK. Consult this when you need to understand a specific package's scope, API surface, or relationship to neighbors. The tier above this one — one paragraph per package — is [catalog.md](catalog.md); the name-only grouping is in [`AGENTS.md`](../../AGENTS.md#package-map).

Where this file and [catalog.md](catalog.md) disagree, catalog.md is the fresher record: it carries package moves (`camera2d` absorbed into `camera`, `quadbatch`/`tilemap` merged into `sprite`, the `scene2d-resources`/`scene3d-resources` layers) that have not been reconciled into the long-form descriptions below.

Run `npm run api <name>` to query exported function signatures directly.

## Core and Primitives

- `@flighthq/types`: shared interfaces, kind symbols, and cross-package type contracts. This is the codebase's header layer — all public API shapes live here.
- `@flighthq/entity`: entity/runtime primitives used by higher-level packages.
- `@flighthq/geometry`: rectangles, vectors, matrices, typed-array capacity helpers, and pools.
- `@flighthq/math`: scalar math utilities — constants (EPSILON, TAU, DEG_TO_RAD), clamping/saturation, interpolation (lerp, inverseLerp, remap, smoothStep, smootherStep, damp, moveTowards, pingPong, repeat, lerpAngle), angles (degToRad, radToDeg, normalizeAngle, deltaAngle), rounding/quantization (roundTo, floorTo, ceilTo, fract, euclideanMod), comparison (approxEqual, approxEqualRelative, approxZero), power-of-two family (nextPowerOfTwo, previousPowerOfTwo, isPowerOfTwo, ceilPowerOfTwo, floorPowerOfTwo, nextMultipleOf), number theory (gcd, lcm, factorial, isEven, isOdd, hypot2, sign, quantize), seeded random and convenience helpers (randomRange, randomInt, randomBool, randomSign), random distributions (randomGaussian, randomGaussianPair, randomOnUnitCircle, randomInsideUnitDisc, randomOnUnitSphere, pick, shuffle, shuffleInPlace, randomWeighted), deterministic hashing (hashUint32, hashCombine, hash2D, hash3D, createRandomSourceFromHash), and statistics (mean, median, variance, standardDeviation, weightedAverage). Pure free functions, no allocation, tree-shakable.
- `@flighthq/layout`: renderer-neutral rectangle layout over a flat parent-before-child tree. A node's container `kind`/style arranges its children while its item style is interpreted by its parent. `resolveLayoutTree` writes x/y/width/height into caller-owned numeric buffers from caller-supplied intrinsic sizes. An open last-write-wins registry installs anchor, flex, grid, or custom policies separately; anchor is a linear forward pass and anchor-only bundles retain no flex/grid code. It reuses `ViewportAlign`, while `ViewportScaleMode` remains a later rectangle-to-node binding concern. Depends only on `types`; constraints, text composition, table semantics, scene binding, and format import stay outside.
- `@flighthq/node`: graph hierarchy, transforms, bounds, appearance, and invalidation.
- `@flighthq/signals`: strictly-typed signals and slots for event dispatching. Signals support multiple listeners, priority, and cancellation. The package is effectively always present in the SDK; specific signal groups are opt-in via `enable*` functions defined in the owning package. Signals is fundamental infrastructure and should have few dependencies.

## Scene Graph and Display

- `@flighthq/scene2d`: retained-mode display objects such as bitmaps, shapes, containers, masks, stages, and videos.
- `@flighthq/text`: text display objects — single-format `TextLabel` and multi-format `RichText` (built on the text-layout spine, with a lazily-ensured layout cache), plus `NativeText`, the platform-rendered text field measured outside the spine by the host engine. ("native-rendered text" is a property of the display object, not a package boundary — the `native` namespace is reserved for the platform/OS-integration suite.)
- `@flighthq/quadbatch`: atlas-based multi-quad scene node and compact instance buffers.
- `@flighthq/tilemap`: atlas-backed tilemap scene node, placement layout, and grid operations.
- `@flighthq/scene3d`: 3D world graph for spatial scene management. A doorway for future development; the road is mostly untaken and the package is not yet built out.
- `@flighthq/clip`: hard geometric clip regions as plain data — constructors (`createClipRegionFrom*` for rectangles, paths, rounded rectangles, ellipses, circles, and raw contours), composition (`intersectClipRegions`, `unionClipRegions`), queries (`clipRegionContainsPoint`, `clipRegionIntersectsRectangle`, `clipRegionContainsRectangle`), transform (`transformClipRegion`; axis-aligned matrices preserve scissor-eligibility, rotation/skew promotes to a quad contour), utilities (`cloneClipRegion`, `copyClipRegion`, `getClipRegionBounds`, `isClipRegionEmpty`, `isClipRegionRectangular`, `equalsClipRegion`, `normalizeClipRegion`, `invalidateClipRegion`), and a pool bracket (`acquireClipRegion`/`releaseClipRegion`). No rendering; rendering is provided by the `scene2d-<backend>` clip modules.
- `@flighthq/path`: the vector-path geometry kernel — 2D outline construction (move/line/quadratic/cubic verbs plus ellipse/circle/rect/round-rect/arc/SVG-arc/polygon/polyline primitives that expand into it), conversion to renderer-consumable forms (flattened polyline contours, ear-clipped fill meshes, pooled typed meshes), measurement/analysis (length, point/tangent at distance, signed area, orientation, true bezier-extrema bounds, winding-rule point containment, segment evaluation), transformation (affine, translate, reverse, stroke-to-outline with joins/caps/dashing), and prepared path morphing (canonical cubic correspondence plus reusable progress sampling). A value-typed leaf (`Path` in → contours/meshes/scalars out) consumed by `clip`/`shape`/`interaction`; it owns the shape, not the pixels or playback. Boolean ops live in `path-boolean`, SVG `d` codecs in `path-formats`. Depends on `types` only.
- `@flighthq/shape`: the retained command recorder for vector drawing — the retained-mode vector `Graphics`-style `Shape` plus a distinct retained `MorphShape` kind over compound prepared path and paint morphs. A flat command vocabulary (moveTo/lineTo/quadratic+cubic curves, arcs, circle/ellipse/rectangle/round-rect/polygon/polyline primitives, raw path injection, indexed `drawTriangles`), solid/gradient/bitmap fills and strokes, exact analytic local-bounds measurement, a solid-fill region resolver (`getShapeFillRegions`), an opt-in per-command hit-test registry with built-in primitive handlers, allocation-stable multi-path and fill/stroke MorphShape sampling with one explicit invalidation, a shape-owned target/visitor binding over scalar animation tracks, and a data-only `Scale9Shape` entity carrying a `scale9Grid`. Canvas/DOM/GL/WebGPU expose default MorphShape renderer aliases over their Shape command renderer. The "what to draw" recorder and MorphShape animation sink; geometry tessellation/flattening/boolean ops are delegated to `path`, clocks/controllers to target-free `animation` or `timeline`, and format serialization to `shape-formats`.
- `@flighthq/path-formats`: tree-shakable serialization codecs for `@flighthq/path`. First-build scope is SVG path data (the `d` attribute): `parseSvgPathData(d): Path | null` parses the full SVG grammar (`M L H V C S Q T A Z`, relative lowercase, implicit repeated commands, the `S`/`T` smooth shorthands, comma/space/scientific-notation/packed-arc-flag tokenizing) into a `Path` via the `appendPath*` builders, and `formatSvgPathData(path, options?)` serializes a `Path` to absolute-command `d` text by walking `forEachPathSegment` (optional coordinate `precision`); `appendSvgPathData(path, d)` parses into an existing path. Codec only — owns no geometry math. Arcs are stored by `@flighthq/path` as cubic beziers, so a round-trip preserves geometry but re-emits `A` as `C`.
- `@flighthq/path-boolean`: 2D constructive-solid-geometry boolean operations for `@flighthq/path` — a tree-shakable neighbor package. Per-operation API `unionPaths(a, b, out?, options?)` / `intersectPaths` / `differencePaths` / `xorPaths` plus the general `booleanPaths(subject, clip, operation, out?, options?)`; each flattens both paths via `flattenPath` at the option tolerance, combines the contours through the active kernel, and rebuilds the result into `out` (a fresh `nonZero` path when omitted, holes traced counter-wound) — `out` may safely alias either input. Operations dispatch through a swappable `PathBooleanBackend` seam (`getPathBooleanBackend`/`setPathBooleanBackend`/`createDefaultPathBooleanBackend`) so a heavier/native/wasm kernel drops in without touching the operation API. The default kernel (`createMartinezPathBooleanBackend`) is a from-scratch floating-point Martinez–Rueda–Feito sweep-line: stage one sweeps to build the segment arrangement (crossing + collinear-overlap subdivision), stage two merges coincident sub-segments by winding, classifies each unique segment by the winding number on each perpendicular side under the fill rule (`PathBooleanOptions.fillRule`, `nonZero` default / `evenOdd`), and traces fill-oriented directed rings. Correct on coincident/overlapping edges, shared vertices, holes, and self-intersecting input; degenerate contours (empty, sub-triangle, zero-area, single point) yield sane empty/passthrough results rather than throwing. Polygon offsetting is `offsetPath(path, delta, options?)` — flatten, offset each contour (miter/bevel/round/square joins with miter-limit fallback; butt/round/square end caps for open paths), then self-union the raw rings through the active kernel to dissolve concave-corner self-overlap and emit a clean hole-correct outline; positive `delta` inflates against a canonical orientation regardless of input winding, over-deflation past self-collapse drops the ring (empty path). `PathOffsetJoin`/`PathOffsetEnd`/`PathOffsetOptions` live in `@flighthq/types`. Region simplification is `simplifyPath(path, options?)` — flatten and self-union a single (possibly self-intersecting/multi-contour) path through the kernel under `options.fillRule` to a clean outline (the Clipper `SimplifyPaths`/Skia `Simplify` op); it shares the module-private `resolvePathRegions` "raw rings → clean region" primitive with `offsetPath`. Kernel-free vertex cleanup (`cleanPath`, dedup coincident/near-collinear/spike vertices) lives in `@flighthq/path`, not here, so dedup never pulls the clipper into a bundle. `unionAllPaths(paths, out?, options?)` folds a path list through one kernel union pass. Positive/negative fill is a path-boolean-local `PathBooleanFillRule = PathWinding | 'positive' | 'negative'` superset (core `PathWinding` stays lean; positive/negative reachable only through the backend seam) — `offsetPath` self-unions under `positive` (Clipper's InflatePaths cleanup fill), correctly dissolving concave-corner self-overlap that non-zero could not. Kernel snap tolerance is magnitude-relative (`extent · 1e-9`); a seeded (xorshift32) fuzz suite asserts union commutativity, `A ∖ A == ∅`, `A ∪ A == simplify(A)`, simplify idempotence, offset identity, convex double-offset stability, and concave-offset self-intersection-freeness. **Full AAA set complete** (all four build phases). Known weak spots (documented in status.md): deflating dense round-join output, and open-polyline-with-coincident-endpoints closedness (unrecoverable from flattened geometry).
- `@flighthq/shape-formats`: tree-shakable serialization codecs for `@flighthq/shape`. Native command-stream JSON uses `formatShapeJson(shape, options?): string` to emit `{ shapeFormat: 2, commands: [{ key, args }] }`, serializing each arg by type (numbers/strings/booleans/numeric arrays verbatim, `Matrix` as `{a,b,c,d,tx,ty}`, `null` verbatim); `parseShapeJson(text, options?): Shape | null` replays each entry through the matching `appendShape*` builder, returning `null` on malformed JSON, a missing/mismatched `shapeFormat` tag, a non-array `commands`, a malformed entry/arg, or an unknown command key. Lossless for every non-texture command. `beginTextureFill`/`lineTextureStyle` textures have no serializable id, so they serialize as an ordinal `ShapeTextureReference` (`{ index }`) and are rehydrated on parse via `options.resolveTexture`; without a resolver (or when it returns `null`) the texture-bearing command is dropped and the rest parses intact. Codec only — owns no drawing, tessellation, or hit-testing. `options.space` pretty-prints. SVG export is a deferred follow-on format.
- `@flighthq/interaction`: hit testing, pointer dispatch, and object overlap detection.

## Rendering

- `@flighthq/render`: renderer registration, render state/queue, render node data, update pipeline, transform/color propagation. Image render caching lives in the renderer packages (`imageRenderCache`, `canvasRenderCache`, `webglRenderCache`, `domRenderCache`), not in a standalone package.
- `@flighthq/render-gl`: WebGL2 backend core — the subject-agnostic GPU plumbing (render state/context, render targets + pool, textures/samplers, shader compilation and material/shader registries, cached pipeline state, fullscreen/quad passes, readback, capability introspection, context-loss detection). Consumed by the `-gl` leaf renderers (`scene2d-gl`, `scene-gl`).
- `@flighthq/render-wgpu`: WebGPU backend core — the sibling of `render-gl`: render-state lifecycle (adapter/device, uniform ring buffer), frame loop (MSAA draw-and-resolve, depth-stencil), pipeline cache + blend table, quad draw path, texture upload/binding, offscreen targets + pool, scissor, fullscreen pass, shader/material registries, frame-capture readback. Consumed by the `-wgpu` leaves (`scene2d-wgpu`, `scene-wgpu`).
- `@flighthq/scene2d-canvas`: Canvas 2D leaf renderer for the 2D display-object family — a per-kind `{createData, submit}` renderer for every display-object node kind (Bitmap, Shape, Scale9Shape, Sprite, QuadBatch, Tilemap, TextLabel, RichText, Video, ParticleEmitter, container) over a shared Canvas draw-state spine, plus blend-mode mapping, clipping, offscreen render targets, and a CSS-filter binding. Host-web-only (`crate: null`).
- `@flighthq/scene2d-dom`: DOM-tree leaf renderer for the 2D display-object family — draws each leaf as live DOM elements reconciled against the document each frame. The only backend that carries real accessibility (ARIA/focus), native CSS/SVG effects (`mix-blend-mode`, `filter`, `<feColorMatrix>`), and HTML/video embedding without emulation. Host-web-only.
- `@flighthq/scene2d-gl`: WebGL2 leaf-renderer suite for the 2D display-object family over `render-gl` — every 2D leaf (bitmap, shape, scale-9, sprite, quad-batch, tilemap, text label, rich text, video, particle emitter, container) plus the GPU-only subsystems with no Canvas equivalent: scissor + stencil clipping/masking, a color-transform material/shader system, render-to-FBO caching (`cacheAsBitmap`), and the velocity (motion-vector) pass.
- `@flighthq/scene2d-wgpu`: WebGPU leaf-renderer set for the 2D display-object family over `render-wgpu` — instanced sprite batching, tessellated-mesh shape rendering, scissor + stencil clipping, off-screen render-cache targets, color-transform materials, a per-state velocity-writer registry, a text-input overlay seam, and a per-frame stats surface. Twin of `scene2d-gl`.
- `@flighthq/scene3d-gl`: WebGL2 forward renderer for the 3D scene graph over `render-gl` — turns a `Node3D`/`Mesh` tree into draw calls with the full mesh-material shader library: a GLSL 300 es Cook-Torrance GGX PBR uber-shader (seven glTF extension lobes) specialized by a `#define` block, plus classic (lambert/phong/blinn-phong), stylized (toon/matcap), attribute (vertex-color/emissive), and debug (normal/depth/wireframe) families — 20 material renderers, registered opt-in. Includes forward punctual lighting (point/spot/hemisphere, `MAX_FORWARD_LIGHTS`=4). Twin of `scene-wgpu`.
- `@flighthq/scene3d-wgpu`: WebGPU (WGSL) forward renderer for the 3D scene/mesh subject over `render-wgpu` — the same 20-material catalogue (Cook-Torrance PBR + KHR extension lobes, classic/NPR/debug families) as its deliberate twin `scene-gl`.
- `@flighthq/adjustments`: the **pointwise value-remap tier** — image operations that map one pixel to one pixel (no neighbors) and therefore _fuse_ (a stack composes to one 4×5 color matrix or one baked LUT) and _fold_ into the draw as per-instance/uniform data rather than bouncing through an offscreen pass. Holds the color-matrix fuse primitives (`concatColorMatrix` + the brightness/contrast/saturation/tint/channel-mixer/color-balance builders, ported from the dissolved `filters`). Color transform is realized as a `HasColorTransform` node trait folded into the sprite/quad batch (per-instance `a_ctMult` or whole-batch `u_ctMult` uniform, chosen by data cardinality; promote-not-split). Sibling of `effects` across the fuse-fold vs chain-bounce line. Full design: [effect-adjustment-architecture.md](../effect-adjustment-architecture.md).
- `@flighthq/materials`: the 3D material system — a full PBR material taxonomy (unlit, Blinn-Phong, metallic-roughness PBR with clearcoat/anisotropy/emissive/transmission, depth). Built (the 20-material taxonomy); canonical design in [3d-materials-architecture.md](../3d-materials-architecture.md). (Color-transform moved out to `adjustments` — it is a post-shading pointwise remap, not a shading input.)
- `@flighthq/effects`: the **spatial/composite tier** — the substrate-agnostic catalog of render effects that read neighbors or need multiple passes/buffers, so they _chain_ (N passes) and _bounce_ through offscreen targets. Plain-data `RenderEffect` descriptors (one `create*Effect` per kind): the spatial ops (blur, sharpen, pixelate, displacement, convolution, median), the full-frame post-process families (color grade, blurs/DoF, bloom/HDR, screen-space 3D, anti-aliasing, film/stylize, lens, accessibility), the composite recipes rehomed from `filters` (drop-shadow, outer/inner glow, inner shadow, bevel, gradient-glow, gradient-bevel), and a `CustomShader` escape hatch — plus deterministic recipe math, per-kind metadata (defaults, required render inputs, field roles), effect-stack validation, and interpolation. Does not execute — pixel work lives in the backends. The pointwise color-grade ops still living here are candidates to re-sort into `adjustments` (see [effect-adjustment-architecture.md](../effect-adjustment-architecture.md) migration staging).
- `@flighthq/effects-gl`: WebGL2 backend for post-process effects — turns the `effects` descriptors into multi-pass fullscreen shader recipes and drives them through the post-process pipeline (MSAA-aware HDR scene target, ping-pong pooled-target loop, per-`GlRenderState` effect registry, program/uniform-location cache, depth/velocity seams). Sibling of `effects-wgpu`/`effects-canvas`; owns the shader recipe per effect, not the descriptors.
- `@flighthq/effects-wgpu`: WebGPU (WGSL) backend for post-process effects — a per-`WgpuRenderState` effect registry, the ping-pong pipeline orchestrator, a compiled-pipeline cache, and 44 effect runners across six taxonomy bands (including mip-chain bloom and three-pass SMAA). The structural twin of `effects-gl` over the same descriptor set.
- `@flighthq/effects-canvas`: Canvas 2D backend for post-process effects — Canvas realizations of the effect set (`ctx.filter` CSS strings, draw-op compositing, per-pixel `getImageData`/`putImageData` passes) plus the opt-in Canvas post-process pipeline (offscreen target, ping-pong scratch pool, per-state runner registry). Host-web-only.
- `@flighthq/velocity`: per-frame per-object 2D motion tracking — a `WeakMap`-backed `VelocityField` any system (transform delta, tween, physics, camera move, manual edit) contributes screen-space velocity into and the GPU motion-blur velocity-buffer writers in `render-gl`/`render-wgpu` read out. Owns the velocity field, the default transform-delta contributor, per-pixel affine sample reconstruction, and value algebra (add/clamp/damp/lerp/normalize/scale) — the conduit between motion sources and post-processing.
- `@flighthq/bitmap`: pixel-level manipulation of `ImageSource` values — read from or generate image data. Not used internally by renderers; user-facing.
- `@flighthq/capture`: the deterministic render-verification policy and format layer — the SDK-side vocabulary the tools, harnesses, and the Rust/wasm `flighthq-capture` parity crate share. Owns tolerant fingerprint comparison, regression/parity evaluation and defaults, tier vocabulary, and the committed baseline record format. Depends on `@flighthq/bitmap` for pixel/fingerprint math. `@flighthq/tool-capture` consumes this policy and owns Playwright execution, server and baseline-file lifecycle, manifest-driven capture/validation, and reporting; the in-page verifier remains in `tools/harness/verify.ts` behind the `window.__ftVerification` contract.

## 3D

The in-scope 3D pipeline's data primitives. The renderable `Mesh`/scene-graph node lives in `@flighthq/scene3d` (Scene Graph), the material system in `@flighthq/materials` (Rendering), and the GL/WGPU forward renderers are `scene-gl`/`scene-wgpu` (Rendering).

- `@flighthq/mesh`: 3D mesh **geometry**, the CPU data layer — interleaved vertex/index buffers, vertex-attribute layouts, parametric primitive builders (box/sphere/plane/cone/cylinder/…), and per-vertex computation (normals, tangents, bounds, bounding sphere), producing `MeshGeometry` values. The three.js `BufferGeometry` analogue. The renderable `Mesh` node lives in `scene`; file parsers producing `MeshGeometry` live in `scene-formats`.
- `@flighthq/lighting`: the data layer of a 3D lighting system — the six light descriptors (`AmbientLight`, `HemisphereLight`, `DirectionalLight`, `PointLight`, `SpotLight`, `AreaLight`), the IBL `Environment`, a photometric-unit seam (`LightUnit` + lux/candela/lumen conversions), a Kelvin→sRGB helper, and descriptor-side culling/luminance primitives. Descriptors + analysis, not a per-fragment shading pass (that is `render`/`scene-*`).
- `@flighthq/texture`: GPU texture-binding descriptors — sampling state (wrap, filter, anisotropy), color space, UV transform (offset/rotation/scale), and the cubemap aggregate. Sits between `@flighthq/image` (the pixel source) and the material/renderer layer; owns the descriptor and its CPU composition, not pixels (`bitmap`) or GPU upload (`render-gl`/`render-wgpu`). Dimension-agnostic — a UV-transformed 2D bitmap consumes the same `Texture`/`Sampler` as a 3D PBR material.
- `@flighthq/camera`: the unified camera math package. `Camera2D` maps a 2D world to a viewport (world↔screen transforms, follow/deadzone/bounds, zoom-at-point, parallax, visible bounds); `Camera3D` supplies perspective/orthographic projection, view/view-projection construction, picking rays, world→screen projection, frustum extraction/culling/corners, eye/basis extraction, and linear-depth recovery. Both remain graph- and renderer-free; draw-time device-pixel `Viewport` aspect is authoritative when a renderer supplies one, while stored aspect remains the standalone/headless fallback. The historical `@flighthq/camera2d` cell is absorbed and must not be recreated.
- `@flighthq/animation`: target-free animation core — keyframe sampling, clip/channel bundling, playback control, crossfades, blend trees, state machines, and layers. Deliberately target-agnostic; domain binding layers (`scene2d`, `scene3d`, `shape`, skeletons, and format adapters) interpret sampled results.
- `@flighthq/skeleton3d`: skeletal animation — joint hierarchies, inverse-bind matrices, and skin-palette computation for GPU upload.
- `@flighthq/picking`: camera-ray scene selection ("click to select" for 3D scenes) — a composition layer over `scene` (raycast traversal) and `camera` (screen-to-world unprojection).
- `@flighthq/scene3d-formats`: 3D scene/mesh file-format parsers — glTF 2.0 (`.gltf`/`.glb`), USD, OBJ, and other exchange formats parsed into Flight's scene/mesh/material/animation graph. (Mesh file formats inherently carry scene structure, so there is no separate `mesh-formats`.)

## Resources

- `@flighthq/image`: image resources — pixel sources and constructors (from canvas/ImageBitmap/element, load from URL/ArrayBuffer/Base64/Blob). MIME detection now lives in `@flighthq/image-codec`; `image` re-exports `detectImageMimeType` for consumers and uses it to type Blobs when loading from bytes.
- `@flighthq/image-codec`: DOM-free byte↔pixel seam. A global MIME-keyed decoder/encoder registry (`registerImageDecoder`/`getImageDecoder`/`hasImageDecoder`/`unregisterImageDecoder`/`clearImageDecoders` and encoder twins), dispatchers `decodeImage(bytes, mimeType?)` / `decodeImagePremultiplied(bytes, mimeType?)` / `encodeImage(image, mimeType, options?)` returning `null` when no codec is registered (decode auto-detects MIME via `detectImageMimeType` when omitted), the migrated `detectImageMimeType` magic-byte sniffer, and opt-in web registrars (`registerWebImageDecoders` over `createImageBitmap`+`OffscreenCanvas`; `registerWebImageEncoders` over `OffscreenCanvas.convertToBlob`). `DecodedImage` is straight RGBA8; the web decoder premultiplies in a JS pass since `getImageData` is always straight. Registry is empty at import (no side effects); depends only on `types`.
- `@flighthq/font`: font and font-resource lifecycle — loaders (name/url/bytes), `document.fonts` load-status queries, magic-byte `detectFontFormat`, and `inferFontFormatFromUrl`.
- `@flighthq/video`: `VideoResource` lifecycle at image parity — load options (crossOrigin/muted/playsInline/preload/readiness), url/blob/mediastream sources, dispose, inspection getters, MIME infer/detect, and codec negotiation.
- `@flighthq/audio`: `AudioResource` lifecycle — the full loader matrix (url/bytes/blob/base64), sample-tier constructors, clone/dispose/predicates, buffer inspection getters, MIME infer/detect, and codec negotiation. (Playback channels + mixer/bus graph live in `@flighthq/media`.)
- `@flighthq/binpack`: the general 2D rectangle bin-packing cell — the geometry primitive underneath texture-atlas building, sprite-sheet layout, tileset assembly, and UI/grid packing, decoupled from all of them (deps `geometry` + `types` only; no pixels, no atlas). Types (in `@flighthq/types` › `BinPack.ts`): `RectangleId` (`string | number`), `PackableRectangle {id, width, height}`, `PackedRectangle {id, x, y, width, height, rotated}`, `BinPackOptions {maxWidth?, maxHeight?, padding?, border?, powerOfTwo?, square?, allowRotation?, growable?}` (defaults: padding 0, border 0, powerOfTwo/square/allowRotation false, growable true, max* = 16384 cap), and `PackResult {placements, width, height, unpacked}`. API: the single one-shot `packRectangles(rects, options?)`. Algorithm: **MaxRects** with the **Best-Short-Side-Fit** heuristic — inputs are sorted by a deterministic total order (descending area, then height, then width, then id) and each is placed into the free rectangle leaving the smallest leftover short side (ties by long side, then top-/left-most free rect, then unrotated); the occupied footprint splits every overlapping free rect into up to four sub-rects (MaxRects split) and contained free rects are pruned. **Padding/border** are geometric, not cosmetic: each piece is inflated to a `(w+padding)×(h+padding)` effective footprint packed into the `(binW−2·border+padding)×(binH−2·border+padding)` usable region, which guarantees ≥`padding` between any two neighbors and ≥`border` from every reported edge. **Rotation** (`allowRotation`) tries the 90° turn as a second candidate orientation, reporting `rotated:true` with swapped `width`/`height`. **Bin sizing**: a fixed bin (`growable:false`) is exactly `maxWidth×maxHeight` and overflow lands in `unpacked`; a growable bin seeds at `ceil(sqrt(totalArea))` (clamped ≥ largest single rect, ≤ cap) and doubles the smaller dimension toward the cap until everything fits or the cap is hit. The reported `width`/`height` is the tight used extent (content + border), then adjusted for `square` (equalize to the larger) and `powerOfTwo` (round each up). **Deterministic**: same input + options → identical `PackResult`; no `Math.random`/`Date`, and the input sort is a total order (no reliance on sort stability). Uses `geometry`'s `intersectsRectangle` for the split's overlap guard. Tested for pairwise non-overlap + in-bounds + size-match over ~20 varied rects, growable fit, fixed-bin overflow, exact padding/border coordinates, power-of-two/square containment, rotation-required fit (and its no-rotation unpacked/grow counterparts), determinism, and edges (empty, single, larger-than-cap). Open directions (charter): a `@flighthq/textureatlas-packer` neighbor composing this + `bitmap`, alternate skyline/guillotine backends behind the same vocabulary, and an incremental/online allocator.
- `@flighthq/textureatlas`: texture atlases — regions, UVs, and constructors over image resources (depends on `@flighthq/image`).
- `@flighthq/texture-formats`: GPU texture-container codec — parses KTX2, DDS, Basis `.basis`, and ATF into described texture peers (dimensions, format, mip chain, array/cube layers, per-level byte ranges), selects a supported peer, and computes fixed-format level layouts without decoding the compressed pixel payload. Transcoding Basis/UASTC/BCn is a separately registered compute-heavy concern. A codec neighbor of the image/texture stack, matching `image-codec`.
- `@flighthq/textureatlas-formats`: texture-atlas descriptor codec — parses (and, maturing, writes) the industry atlas metadata formats (TexturePacker JSON, Starling/Sparrow XML, libGDX/Spine `.atlas`, Aseprite JSON, Cocos plist) into the SDK's `TextureAtlas` region model.

- `@flighthq/loader`: type-agnostic batch load orchestrator over `() => Promise<T>` factories (or `ResourceLoadItem<T>` descriptors). `createResourceLoader`/`queueResourceLoad`/`startResourceLoad` drive a bounded-concurrency worker pool (`setResourceLoaderConcurrency`) with per-item priority (`setResourceLoadPriority`), key dedupe, weight-aware progress, retries with none/linear/exponential backoff, per-item timeouts, and optional token-bucket bandwidth throttling. Batch signals (`onProgress`/`onComplete`/`onError`/`onCancel`/`onPause`/`onResume`) are always present; per-item signals opt in via `enableResourceLoaderItemSignals`. `disposeResourceLoader` detaches listeners. Depends only on `@flighthq/signals` + `@flighthq/types`.
- `@flighthq/assets`: id-keyed asset library layered over `@flighthq/loader` (scheduling) and the per-resource decoders. All state lives on an `AssetLibrary` entity from `createAssetLibrary()` (no module globals); every function takes the library first. Type-agnostic: `registerAssetLoader(library, type, { load, dispose })` binds an `AssetType` to how it loads and frees through an open, last-write-wins registry, so the package depends on `@flighthq/loader` + `@flighthq/signals` + `@flighthq/types` only — never a resource package. `registerAssetDescriptor` is the synchronous catalog atom and `registerAssetManifest` composes it over the plain-data `AssetDescriptor[]` (id → url/type/groups) without loading; replacement reconciles group tags and cannot change a descriptor beneath live holders. `acquireAsset(library, id)` reference-counts and resolves the loaded value: resident → immediate, in-flight → the shared promise (dedup, one `adapter.load` per id across concurrent acquires), else it resolves the descriptor → its type's adapter and loads at refcount 1; failed attempts leave no poisoned entry, so a later acquire retries. `releaseAsset` decrements and, at zero, immediately calls `adapter.dispose(value)` and drops the entry (deterministic free; releasing below zero is a no-op; a release mid-load frees the orphaned value on settle). `getAsset(library, id)` returns the resident value synchronously or `null`; `getAssetRefCount` exposes the holder count. `loadAssetGroup(library, name, options?)` batch-preloads a group's not-yet-resident members through the loader (bounded concurrency, aggregate `AssetLoadProgress` via `options.progress`), acquiring each member so the group stays resident; it rejects after settlement if a member failed, while `releaseAssetGroup` releases successful members. `disposeAssetLibrary` disposes every resident asset and clears the maps. Open directions (charter): LRU size-budget cache at refcount-zero, asset dependency graph, hot reload.
- `@flighthq/scene2d-resources`: renderer-neutral 2D document acquisition and named content resolution. It owns `Scene2DDocument`, enumerable asset/slot references, synchronous reconciliation, operation-scoped async load/progress/cancellation, caller-supplied URL acquisition, and an empty-by-default importer registry.
- `@flighthq/swf`: standalone legacy SWF import domain and the first named-graph source for `Scene2DDocument`. - `@flighthq/easing`: easing functions for use with tween or any animation system.
- `@flighthq/spring`: spring-physics animation — a value that chases a moving target with second-order damped-harmonic motion (accelerate, overshoot, settle), driven by a per-frame `deltaTime` rather than a fixed duration. Plain-data `Spring = { value, velocity }` and mass-independent `SpringConfig = { frequency, dampingRatio }` (frequency in Hz; dampingRatio 0 undamped / <1 underdamped-overshoots / 1 critical-fastest-no-overshoot / >1 overdamped), with `createSpring`, `createSpringConfig`, and `createSpringConfigFromPhysical(stiffness, damping, mass)` (converts k/c/m → `frequency = sqrt(k/m)/(2*PI)`, `dampingRatio = c/(2*sqrt(k*m))`). The core step `updateSpring(spring, target, config, deltaTime)` is the **closed-form analytic** solution of `c'' + 2*zeta*omega*c' + omega^2*c = 0` (`omega = 2*PI*frequency`, `c = value - target`) evaluated exactly over `deltaTime` — three branches (over/critical/under-damped) computing four transition coefficients, then `value/velocity` written from locals. Because it is exact rather than explicit-Euler, it is unconditionally stable (a frequency-1000 spring at `dt = 1` lands on target instead of exploding) and, for a constant target, exactly frame-rate independent (`M(dt)^n == M(n*dt)`); `deltaTime <= 0` and non-positive frequency are no-ops. The `target` is per-step, not stored, so it can change mid-flight. `isSpringSettled` (near target AND near-zero velocity), `resetSpring`, and componentwise `Spring2D`/`Spring3D` (`createSpring2D/3D`, `updateSpring2D/3D`, `isSpring2D/3DSettled`) that apply the one scalar solver per axis. `out`-param, allocation-free hot path. The duration-less, overshoot-capable, second-order complement to `easing`/`tween` (fixed-shape/fixed-duration) and distinct from `math`'s first-order `damp` (no overshoot, no velocity). Depends on `math` + `types` only.
- `@flighthq/motionpath`: path-following animation — advances a marker along a `@flighthq/path` by **arc length** (constant real speed along the curve, not the speed-distorting raw bezier parameter) and reports its world position, tangent, and heading angle, so a caller can move and orient an object along a curve. Plain-data `MotionPath = { path, length, distance, speed, loopMode, direction }` (`distance` = current arc-length position in `[0, length]`; `length` cached at create via `getPathLength`; `speed` a units/sec magnitude; `direction` the `1|-1` travel sign, stored so `pingpong` remembers its heading across frames). `createMotionPath(path, speed?, loopMode?, tolerance?)` measures and caches the length; `updateMotionPath(mp, deltaTime)` advances `distance` by `speed·direction·deltaTime` and resolves the `MotionPathLoopMode` end behavior — `clamp` (stop at the ends), `loop` (wrap modulo length, both directions), or `pingpong` (reflect off each end via a period-`2·length` triangle-wave phase and flip `direction`, correct even when one large `deltaTime` crosses the path several times). `getMotionPathPosition(mp, pointOut, tangentOut)` samples via path's `getPathPositionAtDistance` (returns `false` for an empty/degenerate path); `getMotionPathHeading(mp)` is `atan2` of the tangent (module-scratch, allocation-free); `getMotionPathProgress(mp)` the normalized `0..1`; `setMotionPathDistance`/`setMotionPathProgress` seek with clamping. `deltaTime <= 0` and a zero-length path are no-ops; inputs read to locals before writes (alias-safe on `mp`). The animation-family driver over path's arc-length sampling: path owns geometry and "point at distance D", motionpath owns "where is the marker now and where is it heading" over frames. Depends on `path` + `geometry` + `types` only.

## Game

- `@flighthq/statechart`: concurrent, serializable finite-state graphs shared by gameplay and Rive composition. Immutable `Statechart` descriptors contain Boolean/Number/Trigger inputs, independent regions, open-kind states (`Statechart.Atomic`, `Statechart.Nested`, vendor keys), and authored-order transitions with all-condition guards, exit-time ratios, and blend durations; mutable typed-array `StatechartInstance`s hold one actor's values/states/transitions/elapsed/duration/blend so one chart drives many actors. `advanceStatechartInstance` visits every region against one trigger snapshot, returns the count reaching a new state, and clears triggers only after the whole pass; get-by-name/state/blend queries use `-1` sentinels and `explainStatechartTransition` diagnoses the silent path. Composition supplies the plain duration denominator via `setStatechartRegionDuration`; zero/unset duration coerces to no exit requirement but explains as `MissingRegionDuration` and optionally warns through `enableStatechartGuards`. Blending is reported as a plain weight, never performed; no animation, scene, or format dependency. Entry/exit have no authored callbacks: callers count/read or opt into the separately tree-shakeable `enableStatechartSignals` observer on the mutable instance. The package is distinct from `flow`'s covering closure-bearing screen stack. Dependencies: `types`, plus `signals` and `log` only for separately tree-shakeable observation and guards.

- `@flighthq/collision`: the 2D narrow-phase collision cell — discrete shape-vs-shape overlap between plain-data colliders returning a **contact manifold**, the detection layer queried after a broadphase. Types (in `@flighthq/types` › `Collision.ts`): `CollisionShapeKind` (open string union `circle`/`aabb`/`obb`/`polygon`/`segment`/`point`), the six shape interfaces (`CollisionCircle {x,y,radius}`, `CollisionAabb {minX,minY,maxX,maxY}`, `CollisionObb {x,y,halfW,halfH,rotation}`, `CollisionPolygon {points}` flat convex CCW list, `CollisionSegment {x0,y0,x1,y1}`, `CollisionPoint {x,y}`), the discriminated `CollisionShape` union, and `CollisionManifold {overlapping, normalX, normalY, depth}` (unit minimum-translation axis oriented to push shape **A out of B**, `depth` the penetration; on a miss all zero). API: the ten manifold pair tests `testCircleCircleCollision`/`testCircleAabbCollision`/`testCircleObbCollision`/`testCirclePolygonCollision`/`testAabbAabbCollision`/`testAabbObbCollision`/`testAabbPolygonCollision`/`testObbObbCollision`/`testObbPolygonCollision`/`testPolygonPolygonCollision`, the generic `testCollision(a, b, out)` dispatcher (kind-ranked, negates the normal on reversed argument order), `getCollisionShapeContainsPoint(shape, x, y)`, the boolean segment queries `testSegmentSegmentCollision`/`testSegmentCircleCollision`/`testSegmentAabbCollision`/`testSegmentObbCollision`/`testSegmentPolygonCollision`, and `createCollisionManifold`/`clearCollisionManifold`. **Contact resolution** is a parallel lane over the same ten pairs: `CollisionContactPoint {x,y,depth,featureId}` and `CollisionContactManifold` (the lean fields plus `pointCount` and a fixed, reused two-point `points` array), written by `collide*ContactManifold` (`collideCircleCircleContactManifold` … `collidePolygonPolygonContactManifold`), the generic `collideContactManifold(a, b, out)` dispatcher, and `createCollisionContactManifold`/`clearCollisionContactManifold`. Convex pairs pick the shallowest-separation face as the **reference**, the most anti-parallel face of the other shape as the **incident**, and clip the incident face against the reference face's side planes — up to two points, which is what lets a solver apply torque (an MTV alone has no lever arm, so a box could never tip or rest level); circle pairs are one point on the circle's surface. Each point carries its own `depth` and an opaque `featureId` that is stable while the same features stay in contact, so a physics solver can warm-start from last frame's impulses. **Argument-order invariance holds for pairs of DIFFERENT kinds only**, where the dispatcher's kind rank fixes which shape owns the reference face; two shapes of the SAME kind tie exactly on separation whenever their contacting faces are parallel (a box resting squarely on a box), the tie resolves toward the first argument, and reversing the arguments moves the contact points to the opposite surface and renumbers their ids. That is inherent, not a gap: any order-invariant tie-break would have to be a pure function of the shapes' coordinates, and such a function flips the instant those coordinates cross — hysteresis needs memory of the previous frame, which a stateless narrow phase has none of. **So a caller keying anything on feature identity must pass each pair in a stable order of its own, derived from persistent identity rather than geometry** — `@flighthq/physics2d` orders every pair by body index before it calls. Kept as separate types and entry points so an overlap-only bundle never links the clipping machinery. Convex pairs (AABB/OBB/polygon) run through one shared separating-axis (SAT) core over materialized vertex lists using the min-of-both-directions **separation** penetration (correct for containment); circle pairs are special-cased with closest-point / radial math and a center-to-nearest-vertex axis for corner cases. `out`-parameter and allocation-free in the hot path (box vertices go to module scratch buffers). **Touching is exclusive** (zero penetration → not overlapping) for the manifold tests; the containment/segment queries are boundary-inclusive. Distinct from `@flighthq/geometry` (3D bounding volumes) and `@flighthq/interaction` (display-object hit-testing). Depends on `geometry` + `types`. Phase 1 (discrete overlap + manifolds) and phase 3's contact-point manifolds are built; swept/time-of-impact (phase 2), ray hit fraction/point/normal, and capsule/rounded shapes remain chartered follow-ons.

- `@flighthq/flow`: the application mode/screen flow-state cell — the top-level *screen/mode* stack (boot, menu, play, pause, game-over) with a paired enter/exit/pause/resume/update lifecycle, the small orchestration primitive every engine has (Phaser scenes, a Unity/MonoGame state stack). It is flow control, not save data — serializable application state is a separate concern. Types (in `@flighthq/types` › `Flow.ts`): `FlowState {name?, onEnter?, onExit?, onPause?, onResume?, onUpdate?, updateBelow?, renderBelow?}` — all callbacks optional (`onEnter`/`onExit`/`onPause`/`onResume: () => void`, `onUpdate: (deltaTime) => void`), `name?` is a debug label only, and the two boolean flags mark a transparent overlay whose state beneath keeps updating (`updateBelow`) / stays render-visible (`renderBelow`); `FlowStack {states}` is the stack ordered bottom-to-top (last element = active top), a plain `{states}` with no entity/runtime split and **no module-global stack** (an app holds its own). Lifecycle is **direct callbacks**, not signals — a state's transitions have a single owner (the stack) firing in a defined, deterministic order, exactly when the SDK prefers direct wiring over loose signal dispatch. API (each carries the full `FlowState`/`FlowStack` name): `createFlowStack()` (the only allocator, an empty stack); `pushFlowState(stack, state)` → the current top's `onPause`, then push, then the new state's `onEnter` (pause-then-enter); `popFlowState(stack)` → the top's `onExit`, then the revealed state's `onResume`, returns the popped state or `null` if empty (sentinel, not a throw); `replaceFlowState(stack, state)` → the top's `onExit` + pop then the new state's `onEnter`, **without** pausing/resuming the state below (it stays covered), and a bare push-and-enter on an empty stack; `clearFlowStack(stack)` → `onExit` every state top-to-bottom then empties (no pause/resume — a teardown, not a layering); `updateFlowStack(stack, deltaTime)` → ticks the top's `onUpdate(deltaTime)`, then walks downward ticking the state beneath each visited state that sets `updateBelow`, stopping at the first opaque overlay (a no-op on an empty stack); `getActiveFlowState(stack)` (top or `null`), `getFlowStackDepth(stack)`, and `getFlowStackVisibleStates(stack, out)` which clears then fills `out` with the render-visible states **bottom-to-top** — the top plus its contiguous `renderBelow` run — so the caller draws `out` front-to-back (index 0 first). Small side-effect-free functions over a plain-data stack; depends on `@flighthq/types` only — no display, renderer, or scene graph. Open directions: opt-in `enableFlowStackSignals` transition events, async `onEnter` loading gates over `@flighthq/loader`/`@flighthq/assets`, and cross-fade/slide transition effects.

- `@flighthq/snapshot`: the immutable recoverable-state cell — captures a plain state object into a frozen `Snapshot` value, restores a snapshot back into live mutable state, interpolates between two snapshots, and deep-compares them. It operates on the app's plain model (numbers, strings, booleans, arrays, nested objects — JSON-shaped) but does not own it; the live mutable state lives in the app. It is the save/undo/netcode/replay primitive — "what was the app at this instant," as an immutable value you can store, send, rewind, or tween toward — and the save-data sibling of `@flighthq/flow`'s flow-control stack. Types (in `@flighthq/types` › `Snapshot.ts`): `DeepReadonly<T>` (recursive `readonly`, arrays included; no prior helper existed), `Snapshot<T> = DeepReadonly<T>` (a captured value is deeply-readonly at the type level and deep-frozen at runtime), and `SnapshotSchema` = `readonly string[]` (dot-separated paths from the root, array elements by numeric index — e.g. `'players.0.health'`) selecting which numeric leaves may interpolate. API: `captureSnapshot(source)` deep-clones via the global `structuredClone` then recursively `Object.freeze`s every object/array (immutable and unaliased from the source — mutating `source` afterward never affects the snapshot); `restoreSnapshot(snapshot, target)` deep-assigns fields back into the live mutable `target` in place (preserves `target`'s identity, reuses compatible nested containers, resizes target arrays to the snapshot's length, and clones subtrees so restored state stays mutable and unaliased); `interpolateSnapshots(a, b, t, out, schema?)` clamps `t` to `[0,1]`, walks both snapshots, writes `lerp(a, b, t)` (from `@flighthq/math`) into `out` for each numeric leaf present as a number in both, and **snaps every non-numeric leaf to the destination `b`** (strings, booleans, `null`/`undefined`, one-sided numbers) — with a `schema`, only listed numeric paths lerp and the rest snap to `b`; `equalsSnapshot(a, b)` deep structural equality. Small side-effect-free free functions; the deep-freeze, deep-assign, and interpolation walk are separate internal helpers per file. Depends on `@flighthq/types` + `@flighthq/math` only — no display, renderer, or scene graph, no persistence/serialization format (that is `@flighthq/storage`). Class instances / entity-runtime objects are out of scope; snapshots are of plain data. Open directions: delta compression (`diffSnapshots`/`applySnapshotDelta`), a bounded undo/redo history stack, structural sharing for cheap large-state capture, and `@flighthq/session` integration.
- `@flighthq/spatial`: the 2D broadphase cell — a spatial index over many objects' AABBs that answers "which pairs are close enough to be worth a narrow-phase test?" and "which objects overlap this region/point/ray?" without the O(n²) all-pairs scan. It is the locality filter in front of `@flighthq/collision`'s narrow-phase (and the culling structure a camera/renderer uses to skip off-screen objects). Types (in `@flighthq/types` › `Spatial.ts`): `SpatialObjectId` (a `number` handle — the caller maps its objects to ids; cache-friendly), `SpatialAabb {minX,minY,maxX,maxY}` (spatial's own 2D bounds — structurally like `CollisionAabb` but defined here so spatial never depends on `collision`; distinct from geometry's 3D `Aabb`), `SpatialPair {a,b}` (unordered candidate pair), the `SpatialIndexBackend` seam (`insert`/`update`/`remove`/`clearSpatialIndex`/`querySpatialPairs`/`querySpatialRegion`/`querySpatialPoint`/`querySpatialRay`), and the `SpatialIndex` entity (`{runtime:{backend}}`, entity/runtime split). API: `createSpatialIndex(backend?)` (defaults lazily to a uniform grid, no import side effect), `createUniformGridSpatialBackend(cellSize)`, and the operations dispatching to the backend — `insertSpatialObject`/`updateSpatialObject`/`removeSpatialObject`, `querySpatialPairs(index, out)`, `querySpatialRegion`/`querySpatialPoint`/`querySpatialRay`, `clearSpatialIndex`. All queries fill a caller-provided `out` array (cleared then filled) — no per-call structural allocation. The uniform grid is a spatial hash: an object's AABB maps to the block of `cellSize` cells it covers, each cell holds its co-occupant ids. `querySpatialPairs` emits each co-occupant candidate pair **exactly once** by emitting only from the pair's canonical (top-left of their overlapping cell-ranges) cell — dedup with zero per-pair allocation — and never (a,a); the pair is a broadphase candidate the caller confirms. `querySpatialRegion`/`Point`/`Ray` gather ids from the covered cells (region/ray dedup'd via a reused scratch set) and **confirm each candidate against its real bounds** (rectangle overlap / point-containment via geometry, ray via a slab test), so a false cell-mate is dropped; the ray walks cells with an amanatides-woo DDA bounded to the occupied cell range. Confirmed pairs are invariant to `cellSize` (resolution changes candidates, not confirmed results). Depends on `geometry` (2D AABB/rectangle math) + `types` — **not** `collision`. Phase 1 = the seam + uniform-grid default; quadtree (P2) and sort-and-sweep (P3) are chartered drop-in backends behind the same operations.

Focus managers dispatch pointer/keyboard/wheel events to the focused field: `createTextInputManager` (editable) and `createSelectableRichTextManager` (read-only, selection + copy only), wired to input signals via `connectInputToTextInput`.
- `@flighthq/textlayout`: renderer-agnostic glyph layout engine — line breaking (word-wrap, character-wrap, explicit newlines), horizontal alignment (left/center/right/justify), interWord and interCharacter justification, leading/line-spacing, max-width constraint. Produces positioned `TextLayoutGroup` runs with per-character advance widths. Consumes text-shaper output for measurement.
- `@flighthq/textshaper`: text-shaping seam over a swappable `TextShaperBackend` (`setTextShaperBackend`/`getTextShaperBackend`). Two tiers: a measure-only default (`measureText` — string→width, sufficient for layout + Canvas text) and a full-glyph shaper (`shapeTextRun`/`shapeTextRunInto`/`shapeTextRuns` — glyphs with ids, advances, offsets, clusters, required for GPU text). Also: glyph extents (`getGlyphExtents`/`getGlyphExtentsBatch`/`getGlyphExtentsInto`), font metrics (`getFontMetrics`/`getFontMetricsInto`), caret positions (`getCaretPositionsForRun`), text itemization (`itemizeText`), shaped-run caching (`shapeTextRunCached`), and backend-change signals. Correct international text (Arabic/Indic/kerning/ligatures) needs a full-glyph backend (HarfBuzz). The Rust port mirrors this with `flighthq-textshaper` (rustybuzz backend).
- `@flighthq/textshaper-canvas`: Canvas 2D text-shaper backend — advances-only shaping via the Canvas `measureText` API. Provides `createCanvasTextShaperBackend`/`clearCanvasTextShaperBackendCache`. Sufficient for Canvas-rendered text and layout measurement; does not produce glyph ids or cluster mappings.
- `@flighthq/glyphatlas`: dynamic glyph atlas — the missing primitive that lets vector text render on WebGL/WebGPU (which have no native text): glyphs must be rasterized into a texture atlas and drawn as quads. Owns and defines the shared `GlyphSource` seam (in `@flighthq/types`) that a text renderer consumes — `getGlyphEntry(codepoint)` (region + advance + bearing), `getGlyphKerning`, `getGlyphMetrics` — of which this package is the *dynamic* implementation and the static `@flighthq/bitmapfont` is the other. `createGlyphAtlas(options)` allocates a `@flighthq/bitmap` atlas; `getGlyphAtlasEntry(atlas, codepoint)` returns the cached entry or, on a miss, rasterizes via the active `GlyphRasterizerBackend` (`get`/`set`/`createWebGlyphRasterizerBackend` — web = offscreen-canvas `measureText`/`fillText`→`getImageData`, sentinel `null` where no canvas exists), places the bitmap with an incremental shelf packer, blits its pixels into the atlas bitmap, records the union dirty rect, caches the entry, and manages LRU eviction under `maxGlyphs` (evicted glyphs' space is reclaimed by a `@flighthq/binpack`-style batch repack of the survivors). Read the atlas pixels with `getGlyphAtlasBitmap`, the incremental-upload sub-rect with `getGlyphAtlasDirtyRegion`/`clearGlyphAtlasDirty`, and the `GlyphSource` metrics/kerning with `getGlyphAtlasMetrics`/`getGlyphAtlasKerning`; `createGlyphSourceFromGlyphAtlas` adapts the atlas into the `GlyphSource` method object; `disposeGlyphAtlas` releases the cache. First build is single-page; multi-page spill, SDF/MSDF, `bakeBitmapFont` export, and real font-metric sourcing (metrics are currently derived from font size — the true source is `@flighthq/textshaper` `getFontMetrics`) are charter open directions. Depends on `@flighthq/binpack` + `@flighthq/font` + `@flighthq/geometry` + `@flighthq/bitmap` + `@flighthq/types`.
- `@flighthq/textsegment`: the Unicode text-segmentation seam (UAX #29) — finds grapheme-cluster, word, and sentence boundaries. The *itemize* layer beneath the text stack: a caret moves by grapheme (an emoji or combining sequence is one step), word-select/double-click extends by word, sentence navigation by sentence — `textshaper`/`textlayout`/`textinput`/`bitmaptext` all source boundaries here rather than re-deriving them.
- `@flighthq/bitmaptext`: the QuadBatch-backed bitmap-text display node — lays out a string's glyphs via a `GlyphSource` (per-glyph atlas region, advance, bearing, kerning, line metrics) and emits the result as an `@flighthq/quadbatch` **QuadBatch** of glyph quads. The composition-layer sibling of `movieclip`/`particleemitter`, and the atlas-substrate sibling of renderer-drawn `@flighthq/text`: pre-rasterized glyph quads in one batched draw, so `text` never pulls quadbatch/atlas weight.
- `@flighthq/bitmapfont`: the static bitmap-font cell — a font whose glyphs are pre-rendered into a texture atlas, described by a metrics table (`char → atlas rect + bearing + advance`, plus kerning and line metrics). The **static** implementation of the `GlyphSource` seam that `glyphatlas` defines (both hand a text renderer an atlas + `glyph → region + metrics`, so the GL/WGPU glyph-quad path consumes either agnostically), the games-standard fast-text path (zero runtime rasterization), and the home for SDF/MSDF fonts.
- `@flighthq/bitmapfont-formats`: the codec neighbor of `bitmapfont` — parses the standard AngelCode/BMFont `.fnt` description formats (text, XML, and JSON variants) into a `BitmapFont`, and serializes back. A `-formats` subpackage keeping the parsing weight tree-shakable off the core model, matching `path-formats`/`shape-formats`.

## Application

- `@flighthq/intl`: locale-aware formatting over the ECMAScript `Intl` API — a **utility** (like `math`/`easing`), no `*Backend` seam, since `Intl` is universal to every JS engine Flight targets. Small typed free functions, each fetching-or-building a **cached** `Intl.*` instance keyed by `(kind, locale, serialized-options)`: numbers (`formatNumber`, `formatCurrency`, `formatPercent`, `formatUnit`, `formatCompactNumber`), date/time (`formatDate`/`formatTime`/`formatDateTime` over `Date | number`, documented numeric default field sets), `formatList`, `formatRelativeTime`, plural/ordinal category selection (`selectPluralCategory`/`selectOrdinalCategory` → `Intl.LDMLPluralRule`), and collation (`compareStrings` + a non-mutating `sortStrings`). `locale` is `string | readonly string[]` (`LocaleInput`, in `@flighthq/types`); options mirror the native `Intl.*Options`. The cache is a bounded (256-entry, FIFO-evicting) module-level `Map` of immutable formatter instances — a legitimate memoization cache, not mutable app state — behind a shared `getCached` helper. Invalid input degrades to `Intl`'s own output (`NaN` → `'NaN'`, invalid `Date` → `'Invalid Date'`); a malformed locale/currency that `Intl` throws on stays a throw. Depends on `@flighthq/types` only. Open directions (charter): ICU message formatting (`intl-message`), `Intl.Segmenter`, `Intl.DurationFormat`/`DisplayNames`.
- `@flighthq/application`: optional package providing a main loop, application lifecycle events, and the **windowing API** — `ApplicationWindow` (size/position/state + signals), web event wiring (`attach*`/`detach*`), and window-control commands (title, position, size, minimize/maximize/restore, fullscreen, always-on-top, constraints, `openWindow`, close-with-veto via `onCloseRequest`) over a swappable `WindowBackend` (web default; native hosts register their own), matching the platform suite's backend-seam pattern.
- `@flighthq/log`: leveled, structured, capture-aware logging. Emit side (`log`, `logError/Warn/Info/Debug/Verbose`, `logWith` context variants, `logAssert`, `logOnce`) plus a full listener side: multi-sink fan-out (`addLogSink`/`removeLogSink`/`clearLogSinks`), global and per-channel level gates, `LogContext`-bound contextual loggers, pluggable formatters (`createJsonLogFormatter`/`createTextLogFormatter`), a console-capture sink, an in-memory ring-buffer sink, a file sink over a swappable `LogTransportBackend` (`setLogTransportBackend`/`createWebLogTransportBackend`; web default is a no-op), and sink combinators (buffered/filter/fanout/rate-limited/sampled). Diagnostics extras: timing (`startLogTimer`/`endLogTimer`), tracing spans (`createLogSpan`/`enterLogSpan`/`exitLogSpan`), nesting groups (`beginLogGroup`/`endLogGroup`), field redaction (`setLogRedactionPaths`), custom kind serializers (`registerLogSerializer`), `serializeLogError`, and an opt-in `LogSignals` event group (`enableLogSignals`). Not Canvas/DOM-coupled. Tree-shakes: the emit-only import carries only the gate check and the `LogLevel` enum.
- `@flighthq/debug`: the opt-in debug control panel — the one import a developer reaches for to switch on Flight's diagnostics (per-channel subsystem logging, the relevant guard checks, a dev console sink, timing/markers). Importing it *is* the opt-in; not importing it costs a production bundle nothing. Not the logging mechanism (`log`) or the per-package `enable*Guards`, but the curated umbrella that drives both.
- `@flighthq/useragent`: a pure user-agent string parser — parses `navigator.userAgent` (or an equivalent string) into structured data (browser name/version, OS name/version, engine, device type). A utility, not a platform-integration capability: no `*Backend`, no signals; TS-only.
- `@flighthq/xml`: XML parsing — turning XML text into a traversable document model (and, maturing, serializing back, streaming, and validating).
- `@flighthq/media`: audio and video playback channels.
- `@flighthq/sdk`: convenience barrel for applications and examples.

## Platform Integration Suite

Host/OS integration so applications need no escape hatch out of the SDK. Each capability is a self-contained cell: flat free functions over a swappable `*Backend` (defined in `@flighthq/types`). A web/DOM backend is always lazily available, so every function works on the web; a native host (Electron, Tauri, Capacitor, a C/C++ shell) replaces it via the capability's `set*Backend`. "Electron support" is one backend, not a coupling. Two shapes: **command** capabilities expose flat functions + `get*Backend`/`set*Backend`/`createWeb*Backend`; **event** capabilities expose an entity of signals with `create*`/`attach*`/`detach*`/`dispose*` (mirroring `@flighthq/application`'s window wiring). Web backends guard every API and return sentinels (`null`/`false`/`-1`/`''`/`[]`/no-op) when unavailable rather than throwing.

- `@flighthq/platform`: root identification seam — OS name, desktop/mobile/web kind, arch, locale, touch.
- `@flighthq/accessibility`: explicit-Host assistive-technology bridge — publishes a canvas/game UI's semantics to screen readers, which otherwise see only an opaque `<canvas>`. Its five commands take `HasAccessibilityProvider` first; the provider owns the mirrored ARIA-aligned node tree, focus, announcements, and final `destroy()`. Outcomes are reason-only and method-tight (`ok`, `destroyed`, `no-dom`, plus operation-specific `node-not-found`/`focus-not-moved`). Web alone fills `webHost.accessibility.provider`; its Entity provider and `createWebAccessibilityBackend(container?)` live in `@flighthq/host-web` as a lazy visually-hidden DOM overlay. Native hosts leave the optional slot absent. Core depends only on `@flighthq/types` and never reads the scene graph.
- `@flighthq/clipboard`: explicit system clipboard transport whose free functions take provider-derived `HasClipboard*` Host traits. The top-level `Host.clipboard` group has independent text, image, formats, bookmark, and change slots; unsupported slots are absent rather than sentinel-filled. The open MIME seam (`readClipboardFormat`/`writeClipboardFormat`/`hasClipboardFormat`/`getClipboardFormats`) carries custom flavors, while `readClipboard`/`writeClipboard` batch representations. Expected denial resolves to `''`, `false`, `[]`, `{}`, or `null`. `ClipboardWatch` uses create/attach/detach/dispose and requires both subscribe and unsubscribe.
- `@flighthq/dialog`: file open/save and message/confirm/prompt dialogs.
- `@flighthq/filesystem`: file read/write/list/stat and standard directory paths (web backend over OPFS).
- `@flighthq/notification`: OS notifications and permission.
- `@flighthq/shell`: open external URLs/paths, reveal in folder, move to trash, beep.
- `@flighthq/menu`: native application-menu and context-menu descriptors (native host required to realize).
- `@flighthq/tray`: system tray / menu-bar icon (icon, tooltip, title, context menu, click events). The application/dock badge lives in `@flighthq/app`, not here.
- `@flighthq/shortcut`: global OS hotkeys over a swappable web/native `ShortcutBackend`, plus the accelerator value domain: alias-insensitive parsing and normalization, diagnostic parse errors, platform-aware display labels, equality/validation, enumeration/conflict queries, opt-in trigger signals, and enable/suspend commands. The web backend returns unsupported sentinels; Electron and Tauri adapters provide registration, while their native plugins do not currently realize the enable/suspend semantics.
- `@flighthq/screen`: Host-explicit display enumeration, work area, scale factor, pure current-mode derivation, and Entity-backed display/permission event groups. Web supplies stable query/change/details/permissionChange slots from `@flighthq/host-web`; Electron supplies split query/change slots; no ambient backend registry remains.
- `@flighthq/storage`: synchronous persistent key/value over an explicit `storage.local` Host facet, with method-tight reason envelopes, core-derived namespacing/byte size/typed and JSON access/bulk operations, opt-in change signals through `storage.change`, and resumable checkpointed migrations. Web supplies stable local/change Entity providers over `localStorage`; Electron supplies a configured file-backed Entity using same-directory candidate write + rename. Mutation `reason: 'ok'` means atomic visibility and cache agreement, not fsync or power-loss durability; quota estimation and ambient backend selection are out of scope.
- `@flighthq/device`: static device/OS identity — model, manufacturer, OS, memory, safe-area insets. Battery is _not_ here; it is a live concern owned by `@flighthq/power`.
- `@flighthq/share`: explicit system share-sheet invocation through top-level content/files Host slots,
  payload validation, boolean and detailed-result calls, and core-owned opt-in result signals. Web
  realizes title/text/URL plus portable data-URL files; Capacitor realizes title/text/URL and exposes
  its chooser title only on the concrete provider extension.
- `@flighthq/haptics`: vibration and impact/notification/selection feedback.
- `@flighthq/geolocation`: current position and position watches.
- `@flighthq/webcam`: take photo / pick image.
- `@flighthq/statusbar`: mobile status-bar control over a swappable web/native `StatusBarBackend`: foreground style, animated visibility, packed-RGBA background color, content overlay, snapshot/height reads, explicitly attached change signals, and a baseline-restoring component style stack with push/pop/has/clear lifecycle. The web backend maps color to the theme-color meta hint; the Capacitor adapter realizes mobile setters and a construction-time cached snapshot.
- `@flighthq/net` (command): HTTP(S) transport — the URLLoader/URLRequest home. `sendNetRequest(request, options?)` over a swappable `NetBackend` (`getNetBackend`/`setNetBackend`/`createWebNetBackend`); plain-data `NetRequest`/`NetResponse`, `text`/`json`/`arraybuffer`/`blob` decode, timeout + `AbortSignal` cancellation, opt-in download-progress signal. Expected transport failures (network error, DNS, timeout) resolve to a sentinel `NetResponse` (status 0, ok false); a non-2xx is a normal response with the real status. Distinct from `@flighthq/connectivity` connectivity status.
- `@flighthq/socket` (event): bidirectional persistent-connection transport — the Socket/WebSocket/XMLSocket home, the long-lived sibling of `@flighthq/net` (one-shot request/response). A plain `Socket` entity plus an opaque `SocketRuntime` (live connection + opt-in signals + readyState) over a swappable `SocketBackend` (`getSocketBackend`/`setSocketBackend`/`createWebSocketBackend`, DOM `WebSocket` by default, lazy and import-side-effect-free). `createSocket(options)` opens; `attachSocket`/`detachSocket` gate event delivery; `disposeSocket` closes-if-open then detaches and drops the signal group (dispose is entity teardown, distinct from the `closeSocket` connection command). Commands: `sendSocketMessage` (text/binary; sentinel `false` when not open, never throws), `closeSocket` (code/reason), `getSocketReadyState` (`connecting`/`open`/`closing`/`closed`). Typed events opt-in via `enableSocketSignals` → `onSocketOpen`/`onSocketMessage` (text vs binary `SocketMessage`)/`onSocketClose` (`SocketCloseInfo` code/reason/wasClean)/`onSocketError`. Web backend returns a null connection for unsupported transports (raw TCP/UDP); native hosts add them via `setSocketBackend`. Distinct from `@flighthq/connectivity` connectivity status.
- `@flighthq/permissions` (command): OS-permission query/request — the shared "may I?" gate the capability packages (webcam/geolocation/notification/clipboard) sit behind. `getPermissionState(name)` (query, non-prompting) and `requestPermission(name)` (may trigger the OS prompt) over a swappable `PermissionBackend` (`getPermissionBackend`/`setPermissionBackend`/`createWebPermissionBackend`). `PermissionName` = open string union (`'camera'|'microphone'|'geolocation'|'notifications'|'clipboard-read'|'clipboard-write'|'persistent-storage'|'push'|'midi'|'screen-wake-lock' | (string & {})`); `PermissionState` = `'granted'|'denied'|'prompt'` (the Permissions-API vocabulary; `'prompt'` = not yet decided). Web backend queries via `navigator.permissions.query({ name })` (name→descriptor map; identity for the built-ins), falling back to `Notification.permission` (`'default'`→`'prompt'`) for notifications and the `'prompt'` sentinel otherwise when the API is absent or the name is unqueryable. `request` routes each name to its real web trigger — notifications → `Notification.requestPermission`, camera/microphone → `getUserMedia({video/audio})` then stop the granted tracks immediately, geolocation → a one-shot `getCurrentPosition`, persistent-storage → `navigator.storage.persist` — and a name with no request path falls back to a plain state query. A missing API resolves to a `'prompt'`/`'denied'` sentinel; nothing throws. State + request only: it never opens the stream, reads the location, or shows the notification — the capability packages do that. Depends on `@flighthq/types` + the DOM.
- `@flighthq/connectivity` (event): connectivity status and online/offline signals.
- `@flighthq/power` (event): battery/charging status, low-power and keep-awake.
- `@flighthq/lifecycle` (event): app active/inactive/background, resume/pause, back button.
- `@flighthq/keyboard` (event): on-screen keyboard visibility/height (type `SoftKeyboard`, avoiding the DOM `Keyboard`).
- `@flighthq/sensors` (event): accelerometer, gyroscope, device orientation.

Application/process layer (host shell integration beyond a single window):

- `@flighthq/app`: application identity (name/version/locale), control (quit/relaunch/focus), single-instance lock + `onSecondInstance`, the canonical app badge (`setAppBadgeCount`) + dock badge/menu/bounce, and app events (`onActivate`, `onOpenFile`).
- `@flighthq/protocol`: custom URI-scheme / deep-link registration plus an `onOpenURL` handler entity.
- `@flighthq/updater` (event): auto-update lifecycle — checking/available/progress/downloaded/error signals plus check/download/quit-and-install commands.
- `@flighthq/ipc`: inter-process messaging — `sendIpcMessage`, `invokeIpc`, `onIpcMessage` over a host channel backend (for split-process hosts like Electron main↔renderer).

Inbound host events are delivered through explicit event slots and Entity attachment — for example `attachScreenSignals(host, signals)` binds `Host.screen.change`. Other domains still expose their existing subscription surfaces while awaiting their own migration slices. The window backend delivers OS-originated changes by mutating the `ApplicationWindow` and emitting its signals directly (it owns the `win`↔OS-window mapping from `openWindow`); native window backends additionally implement icon/opacity/progress/attention/skip-taskbar/menu-bar/parent controls.

Host backends (the concrete adapters that fill the seams) are a distinct package class — they carry a host dependency, are not tree-shakable, and are named `host-<runtime>`:

- `@flighthq/host-electron`: Electron main-process implementation of the window/app/dialog/clipboard/menu/tray/shortcut/screen/power/notification/shell/protocol/updater/ipc seams. The consumer passes the `electron` module explicitly — `registerElectronBackends(electron)` — typed against a local `ElectronApi` interface (the exact Electron surface Flight depends on), so the package needs no `electron` dependency and is unit-testable with a fake. Each `createElectron*Backend(electron)` is also exported for granular use. **Not** re-exported from `@flighthq/sdk` (it is an adapter you install in the host process, not app-facing API). Mobile seams and `filesystem` (node `fs`) are out of scope here — a future `host-capacitor` / a node-fs injection covers those. Future siblings: `host-tauri`, `host-capacitor`.

Tooling suite (`tool-*` — the dev/CI sibling of `host-*`: harness/build/test tooling that may carry a Node/Playwright runner plus a browser-side protocol adapter selected through the same root's `browser` condition, and is **not** re-exported from `@flighthq/sdk`):

- `@flighthq/tool-capture`: the capture, visual-verification, and performance harness (first `tool-*` member) — drives arbitrary manifest routes and Flight's built-in suites in a deterministic headless browser; produces screenshots/logs/status and versioned aggregate reports; gates non-blank readback, fingerprints, DOM/canvas/WebGL/WebGPU parity, and regression; samples repeatable work behind backend completion fences; and composes many resources/subjects through one batch workflow. Its small page adapter publishes the versioned verification/benchmark protocol; the runner owns Playwright/Node I/O and consumes `@flighthq/capture` policy; excluded from `@flighthq/sdk`.
